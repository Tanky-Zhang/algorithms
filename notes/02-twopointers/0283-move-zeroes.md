# 283. 移动零 · 简单

来源：[力扣官方题目](https://leetcode.cn/problems/move-zeroes/description/)，2026-11-25 核对。以下为题意转述。

原地修改整数数组，将所有零放到末尾，非零元素保持原来的相对顺序。不能复制数组来完成算法；方法无返回值，直接修改传入的 nums。

约束：1 ≤ nums.length ≤ 10^4，元素为 Java int 全范围。

示例：[0,1,0,3,12] → [1,3,12,0,0]；[0] → [0]。

模板：src/main/java/com/tanky/hot100/twopointers/MoveZeroes.java。
测试：src/test/java/com/tanky/hot100/twopointers/MoveZeroesTest.java。
运行：mvn -Dtest=MoveZeroesTest test。

9 组测试覆盖单元素、全零、无零、连续零、负数、重复非零值及 int 边界。测试对传入数组验证结果，空间复杂度与操作次数仍需代码审查。

## 本人思路

最初提出左右向中间交换，经 [0,1,2] 反例发现会破坏非零顺序。讨论后采用同向双指针：扫描指针逐项前进，放置指针仅在放入非零元素时前进。

## 通用思想与面试表达

2026-11-25 13:31 +08:00：修正后执行 mvn -Dtest=MoveZeroesTest test，9 组全部通过，失败 0、错误 0、跳过 0。未修改学员算法代码。

正确性不变量：每轮开始时 [0,l) 为按原顺序放好的非零元素，[l,r) 全为零，[r,n) 待扫描。遇到非零值时交换到 l 并推进两个指针，遇零仅推进 r，保持上述不变量。结束时所有非零元素在前且顺序不变，剩余位置均为零。

时间 O(n)，空间 O(1)。r 每轮递增一次；算法不申请额外数组，不对元素做算术，int 边界值同样安全。l<=r 始终成立，循环条件中的该检查冗余但不影响正确性；l==r 时交换自身也正确，可选跳过以减少写操作。可自行统一缩进、运算符空格并用 write/read 表达指针职责。

面试表达：扫描指针按原顺序访问每个元素，放置指针记录下一个非零元素的位置。遇到非零值时交换到放置位置，因此非零顺序不变；一次扫描、常数额外空间。
