# 11. 盛最多水的容器 · 中等

来源：[力扣官方题目](https://leetcode.cn/problems/container-with-most-water/description/)，2026-11-25 核对。以下为题意转述。

数组 height 中的每个数代表对应横坐标处的一条竖线高度。选取两条竖线，与横轴构成不能倾斜的容器，返回最大盛水量。两线之间的其他竖线不影响该容器的容量。

约束：2 ≤ height.length ≤ 10^5；0 ≤ height[i] ≤ 10^4。

示例：[1,8,6,2,5,4,8,3,7] → 49，对应下标 1 和 8 的两条线。
[1,1] → 1；[0,0] → 0。

模板：src/main/java/com/tanky/hot100/twopointers/ContainerWithMostWater.java。
测试：src/test/java/com/tanky/hot100/twopointers/ContainerWithMostWaterTest.java。
运行：mvn -Dtest=ContainerWithMostWaterTest test。

10 组测试包含官方示例、最小长度、零高度、不同高度、等高、递增、递减、内部最优、两端最优和最大规模。最大规模用于观察可扩展性，不以固定超时阈值作为复杂度证明。

## 本人思路

讨论后确认：容量是两线较小高度乘以下标间距；从两端开始，每次更新最大容量并移动较短的一侧，因为保留短边只移动高边不可能超过当前容量。

正确性：容量取较小高度乘间距；每次计算后移动短边。固定短边只向内移动另一端，宽度减小且水位不会高于该短边，因此此类配对不可能超过当前容量，可以安全舍弃该短边。等高时移动任意一侧均成立；每轮保留历史最大值。

边界：两元素、零高度、等高、递增递减及最大规模均测试通过。最大容量为 10000×99999=999990000，不会溢出 int。

复杂度：每轮一个指针向内移动，至多 n-1 轮，时间 O(n)、额外空间 O(1)。

代码质量：可自行删除过时 TODO 和已注释的异常，统一缩进及运算符空格。

面试表达：从最大宽度开始计算容量，每次舍弃较短的边。保留短边移动高边不可能改善当前容量，因此不会漏掉最优解。两指针相遇时结束，时间 O(n)，空间 O(1)。
